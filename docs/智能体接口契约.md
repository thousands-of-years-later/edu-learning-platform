# 智能体接口契约

面向 App / H5 / 联调脚本。所有接口都在同一台后端（p01 测试服 `http://192.168.100.3:1000`）。

## 一、通用约定

- **前缀**：主前缀 `/api/v1/agent`；`/agent` 是兼容别名，两者行为、鉴权完全一致，新代码请用 `/api/v1/agent`。
- **鉴权**：`Authorization: Bearer <token>`。未带或失效返回 JSON 401（`code=401`），不会 302 到登录页。
- **响应**：`{"code":0,"msg":"操作成功", ...}`，`code=0` 为成功；业务失败时 `msg` 可直接展示。
- **用户身份**：服务端从 Token 取 `userId`，客户端**不要**传 `userId`，传了也会被忽略。

## 二、接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/agent/chat` | 课程问答，建会话、落消息、返回 `sessionId` |
| POST | `/agent/chat/ask` | 课程问答，纯代理、不落库（一次性问答） |
| POST | `/agent/chat/stream` | 课程问答流式，立即返回 `requestId`，内容走 WebSocket |
| POST | `/agent/community/ask` | 帖子问答，会落会话（`scene=community`）；`answer` 正文不带来源标注，来源统一看 `refs` |
| POST | `/agent/sql/ask` | 自然语言转 SQL（只读视图），结果落历史成表格消息 |
| POST | `/agent/video/summary` | 视频总结，异步任务 |
| POST | `/agent/video/subtitle` | 视频字幕（SRT/VTT），异步任务；已生成过直接返回缓存地址 |
| POST | `/agent/ppt/generate` | PPT 生成，异步任务 |
| GET | `/agent/tasks/{taskId}` | 任务状态与结果 |
| POST | `/agent/sessions` | 新建会话 |
| GET | `/agent/sessions` | 会话列表（分页） |
| GET | `/agent/sessions/{sessionId}/messages` | 消息列表（`beforeMessageId` 游标） |
| PUT | `/agent/sessions/{sessionId}` | 重命名会话 |
| DELETE | `/agent/sessions/{sessionId}` | 软删会话 |
| GET | `/agent/memories` | 长期记忆列表 |
| POST | `/agent/memories` | 新增记忆 |
| PUT | `/agent/memories/{memoryId}` | 更新记忆内容 |
| DELETE | `/agent/memories/{memoryId}` | 删除记忆 |
| POST | `/api/v1/upload/image` | 聊天图片上传（注意前缀是 `/api/v1/upload`，不在 agent 下） |

### 会话场景（scene）

| scene | 产生来源 |
| --- | --- |
| `course` | `/chat`、`/chat/ask`、`/chat/stream` |
| `sql` | `/sql/ask` |
| `ppt` | `/ppt/generate` |
| `video` | `/video/summary`、`/video/subtitle` |
| `community` | `/community/ask` |
| `chat` | 用户手动新建的会话 |

会话标题取用户原始问题 / PPT 主题，视频类会话固定为 `视频总结：{小节名}`、`视频字幕：{小节名}`（如“视频总结：01-环境搭建与第一个程序”）；取不到小节名时降级为“视频总结”“视频字幕”。`videoId` 只留在任务的 `inputJson` 里，不再拼进标题。

## 三、长期记忆

记忆是**用户级**，不绑定会话，跨会话生效。

- 新增：`POST /agent/memories`，body `{"content":"..."}` → `{"memoryId":1}`
- 列表：`GET /agent/memories` → `{"total":1,"rows":[{memoryId,content,source,status,createTime,updateTime}]}`
- 更新：`PUT /agent/memories/{memoryId}`，body `{"content":"..."}`（不用再删+建）
- 删除：`DELETE /agent/memories/{memoryId}`，幂等

限制（前端做输入校验用）：

- 单条 **500 字**，超出后端截断；
- 单用户最多 **50 条**，超了返回 `msg="记忆条数已达上限（50），请先删除部分记忆"`；
- 注入模型时只取最近 **20 条**、每条截 **200 字**；
- `source` 默认 `manual`，App 传 `app` 便于区分。

注入范围：`/agent/chat`、`/agent/chat/ask`、`/agent/chat/stream` 都会注入；`/community/ask`、`/sql/ask` 不注入。

注意：记忆内容会直接进 prompt，客户端要提示用户不要存密码、身份证号这类敏感信息。

### 记忆候选（模型提议，用户确认）

`POST /agent/chat` 的响应可能多一个 `memoryCandidates`：

```json
{"memoryCandidates":[{"candidateId":"a1b2c3d4e5f6","content":"姓名王五，从事软件测试开发工作","reason":"模型从本轮对话中识别"}]}
```

- 只在用户本轮表达稳定个人信息或偏好时出现，普通课程问题不带这个字段；
- `candidateId` 由内容哈希生成，同一句话固定不变，前端可用它去重、记录“已忽略/已保存”；
- 后端已做规范化去重（同一事实的不同措辞合并）、最多返回 3 条、过滤“希望助手记住…”这类元信息；
- `answer` 已剥离全部标记，包括输出被截断时的半截标记；前端兜底只需做长度和条数校验，不必再写正则剥离；
- 前端展示“要记住这条吗？[保存] [忽略]”，保存时调 `POST /agent/memories`（body 只要 `{"content":...}`），忽略就不调；
- `POST /agent/memories` 已做幂等：同一用户下内容完全相同的记忆只保留一条，重复点“保存”不会叠加；
- 流式 `/chat/stream` 不提供候选，避免标记混进增量文本。

## 四、图片提问
1. 先上传：`POST /api/v1/upload/image`，`multipart/form-data`，字段名 `file`
   - 单张 ≤ 5MB，只接受 JPEG / PNG / GIF / WebP（按文件头判断，不看扩展名）
   - 单用户每天 20 张（进程内计数，重启清零）
   - 返回 `{"code":0,"url":"https://...","objectKey":"agent/chat/{userId}/..."}`
2. 再提问：`POST /agent/chat`，body 里带
   ```json
   {"question":"这道题怎么做","imageUrls":["<上一步返回的 url>"]}
   ```
   - 最多 3 张；
   - `imageUrls` 必须是上传接口返回的 `agent/chat/` 前缀地址，否则会被拒绝；
   - 只传图不带文字时，服务端用默认问题“请描述这张图片的内容”；
   - 消息 `contentType` 会是 `image_text`。

## 五、异步任务

`ppt/generate` 入参：`{topic, content?, pages?, videoId?, sessionId?}`

- `topic` 只做标题，最长 **100 字**；超长直接返回中文错误“PPT 主题最长 100 字（当前 N 字）；正文素材请放到 content 字段”；
- `content` 是正文素材（视频总结、字幕、课程笔记等），最长 **8000 字**，超长返回中文错误；生成时只取前 4000 字参与大纲；
- `videoId` 可选，仅作为来源标记透传到结果里，不参与生成。

- `video/summary`、`video/subtitle`、`ppt/generate` 立即返回 `{"taskId":1,"status":"PENDING","sessionId":20,"messageId":40}`。
- 三者都支持可选 `sessionId`：不传就新建一个会话，并落两条消息（user + `contentType=task` 的 assistant）；传了就挂到已有会话，从历史能直接打开结果卡。
- `GET /agent/tasks/{taskId}` 的 `task.progress` 目前是三段值：`0`（PENDING）、`5`（RUNNING）、`100`（SUCCESS）；前端按阶段展示即可，不要当成连续百分比。`
- 轮询 `GET /agent/tasks/{taskId}`，`task.status` 枚举：`PENDING / RUNNING / SUCCESS / FAILED`。
- `task.outputJson` 是 **JSON 字符串**，需要二次解析：
  - PPT：`{url, fileName, pageCount, slides[], outline{title,subtitle,sections,highlights,keyPoints,closing}, videoId}`
    - `pageCount` 是页数（当前固定 6），`slides` 是结构化页数组：`[{page, type, title, bullets[]}]`，`type` 为 `cover / contents / section / highlights / keyPoints / closing`；
    - 历史旧任务里 `slides` 仍是数字、并且没有 `pageCount`：前端遇到 `typeof slides === "number"` 时按旧结构降级（只展示 `outline`），不要当作数组遍历。
  - 视频：`{videoId, courseId, videoTitle, durationMinutes, summary, transcriptChars, asr, fallback, asrErrorCode, subtitleUrl, subtitleVttUrl, subtitleFormat, subtitleSegments}`
    - `fallback=true` 表示没跑通语音识别，`summary` 是元数据摘要，原因写在一句中文里（如“视频地址不是公网可访问地址，无法进行语音识别”），**不会出现原始 JSON 或 request_id**；
    - `asrErrorCode` 是内部错误码（如 `FILE_DOWNLOAD_FAILED`），前端可以不展示，用于排查；
    - 字幕字段复用同一次 ASR，成功时必带；字幕生成失败不影响总结。
  - 字幕：`{videoId, courseId, videoTitle, durationMinutes, subtitleUrl, subtitleVttUrl, subtitleFormat, subtitleSegments, transcriptChars, cached, asr}`
    - `subtitleUrl` 是 OSS 上的 `.srt` 直链（公共读），`subtitleVttUrl` 是 `.vtt`，可直接挂给浏览器 `<track>`；
    - `cached=true` 表示命中已生成字幕，不再重跑 ASR；body 传 `{"force":true}` 可强制重转；
    - 只跑 ASR、不调用大模型，通常比 `video/summary` 快一截。
- 失败时 `task.errorMsg` 已清洗成一句话中文，可直接展示（如“视频不存在或已删除”），不再带 `500 Internal Server Error` 和 JSON 片段。

### SQL 问答的结果卡

`POST /agent/sql/ask`，body `{question, sessionId?}`，返回 `{answer, sql, rows, rowCount, error, sessionId, messageId}`。

同时落一条 `contentType=table` 的 assistant 消息，`resultJson` 存 `{sql, rows 前 20 行, rowCount, error}`；历史里按第七节的规则渲染表格。

## 六、流式协议（WebSocket）

### 连接

```
ws://<host>/ws/forum?token=<API_TOKEN>
```

握手时校验 Token，失败直接断开。连接建立后必须先订阅自己的 topic：

```json
{"action":"subscribe","topics":["user:123"]}
```

`user:{userId}` 只允许订阅自己，订阅别人的会收到 `{"type":"error","msg":"无权订阅该主题"}`。

### 客户端 → 服务端

| 报文 | 说明 |
|---|---|
| `{"action":"subscribe","topics":["user:123"]}` | 订阅事件 |
| `{"action":"unsubscribe","topics":["user:123"]}` | 取消订阅 |
| `{"action":"ping"}` | 心跳，服务端回 `{"type":"pong","ts":...}` |

### 服务端 → 客户端

统一信封：

```json
{"type":"agent.delta","eventId":"e-123","ts":1732580000000,"data":{...}}
```

| type | data 字段 | 时机 |
|---|---|---|
| `agent.start` | `requestId`, `sessionId` | 开始处理 |
| `agent.delta` | `requestId`, `seq`, `content` | 增量文本，`seq` 从 1 递增 |
| `agent.done` | `requestId`, `sessionId`, `messageId`, `answer`, `refs` | 正常结束 |
| `agent.error` | `requestId`, `code`, `message` | 失败结束，`code` 目前为 `STREAM_FAILED` |

客户端处理要点：

1. 用 `requestId` 匹配本次请求（同一用户可能并发多个流）；
2. **结束标记只有 `agent.done` 或 `agent.error`**，不要靠空 `delta` 判断；
3. 收到 `agent.error` 后停止拼接，展示 `data.message`；
4. `agent.done` 的 `answer` 是完整全文，可与已拼接内容对账；
5. 断线重连后需要重新 `subscribe`，服务端不保证补发历史事件。

调用流程：

```
POST /agent/chat/stream {"question":"...","sessionId":?,"courseId":?}
  → {"code":0,"requestId":"...","sessionId":12}
  → WS 依次收到 agent.start / agent.delta... / agent.done
```

## 七、历史会话的恢复范围

`GET /agent/sessions/{id}/messages` 返回的每条消息：

| 字段 | 说明 |
|---|---|
| `content` | 文字内容，直接展示 |
| `contentType` | `text` / `image_text` / `table` / `task` |
| `refsJson` | 课程/帖子引用，JSON 字符串，需二次解析 |
| `taskId` | 结果卡关联的异步任务 ID，没有则为 null |
| `task` | 后端联查出的任务对象：`taskType / status / progress / outputJson / errorMsg`，没有则为 null |
| `resultJson` | 结构化结果快照，SQL 表格用，JSON 字符串 |

前端渲染规则：

- `contentType=text|image_text`：普通气泡
- `contentType=table`：解析 `resultJson` 渲染表格（`sql / rows / rowCount / error`，最多存 20 行）
- `contentType=task`：读 `task.status`
  - `PENDING/RUNNING`：显示进度占位
  - `SUCCESS`：解析 `task.outputJson` 渲染 PPT 卡（`url/fileName/pageCount/slides[]/outline`）或视频卡（`summary/durationMinutes`）
  - `FAILED`：直接展示 `task.errorMsg`（已是中文短句）
- `taskId=null` 的老消息：按纯文本降级，不要报错

`outputJson` 是字符串，需要二次 JSON 解析；PPT 的 `url` 是公共读直连地址，无时效。

## 八、未实现 / 暂不支持

- 记忆全自动抽取（对话结束后由模型直接写入）：未实现。当前只做到“模型提议 + 用户确认”，确认后仍走 `POST /agent/memories`。
- 记忆全局开关：未实现，目前只能逐条删除。
- 会话级记忆隔离：记忆是用户级，没有“本会话不启用记忆”的参数。

## 九、执行型智能体 `/agent/act`

一次请求跑一个 function calling 循环：模型输出 `tool_call` → 服务端执行 → observation 回填 → 模型决定继续或收尾。过程逐步落库，前端轮询拿步骤。

### 9.1 提交任务

`POST /agent/act`（同 `POST /api/v1/agent/act`）

```json
{
  "goal": "总结 videoId=201 这个视频，并做成 6 页 PPT",
  "sessionId": null,
  "maxSteps": 8
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `goal` | 是 | 1–500 字，自然语言目标 |
| `sessionId` | 否 | 不传则新建会话，`scene=act`，标题取 goal 前 30 字 |
| `maxSteps` | 否 | 模型轮次上限，默认 8，服务端夹到 1–10 |

`goal` 超过 500 字返回 `{"code":400,"msg":"目标最长 500 字（当前 N 字）"}`。

响应：

```json
{ "code": 0, "msg": "操作成功", "taskId": 58, "status": "PENDING", "sessionId": 88 }
```

任务为异步：接口立即返回 `taskId`，执行在后台线程跑。

### 9.2 轮询步骤

`GET /agent/act/{taskId}`

```json
{
  "code": 0,
  "task": { "taskId": 58, "status": "SUCCESS", "progress": 100, "taskType": "act", "...": "..." },
  "steps": [
    { "seq": 1, "stepType": "thought", "toolName": null, "argsJson": null, "observationJson": null,
      "status": null, "errorCode": null, "elapsedMs": null },
    { "seq": 2, "stepType": "tool", "toolName": "summarize_video",
      "argsJson": "{\"videoId\":201}", "observationJson": null, "status": null, "elapsedMs": null },
    { "seq": 3, "stepType": "observation", "toolName": "summarize_video",
      "observationJson": "{\"ok\":true,\"summary\":\"...\"}", "status": "ok", "errorCode": null, "elapsedMs": 38035 }
  ],
  "answer": "已完成。……"
}
```

要点：

- 只返回当前用户的任务；`task` 归属校验失败按无权限处理。
- `argsJson` / `observationJson` 是**字符串**，前端要二次 `JSON.parse`。
- `stepType`：`thought`（模型意图）、`tool`（调用）、`observation`（结果）。`final` 不落库，收尾文本在 `answer`。
- `answer` 从 `task.outputJson` 解析，`FAILED` 时为 `null`。
- `status=FAILED` 时 `task.errorMsg` 形如 `[STEP_LIMIT] 已达到最大步数 8`，已完成步骤仍保留，前端可以展示"走到哪一步"。

### 9.3 工具

6 个工具：`search_course`、`ask_community`、`query_learning_stats`、`summarize_video`、`generate_ppt`、`save_memory`。完整参数、返回、使用边界见 `p01智能体工具清单.md`。

- 工具由服务端注册表白名单控制，模型不能调用名单外的工具。
- `save_memory` 通过 Java 内部接口落库（`POST /internal/agent/memory`，`x-internal-token` 校验），agent 本身只有只读库权限。
- `query_learning_stats` 的 `observation.sql` 只用于审计，前端步骤展示应隐藏。

### 9.4 护栏

| 项 | 值 |
|---|---|
| 步数 | 默认 8，硬上限 10（`maxSteps` 越界自动夹取，不报错） |
| 单工具超时 | 检索 15/25s、统计 20s、视频与 PPT 120s、记忆 10s |
| 总超时 | 300s（`ACT_TIMEOUT`） |
| 成本 | 单次 act 最多 1 次 `summarize_video`、1 次 `generate_ppt` |
| 失败 | 连续 2 次工具失败终止（`TOOL_FAILED`）；单次失败回填 `errorCode + hint`，模型可换路 |
| 审计 | 每步 `task_id/user_id/tool/args/observation/耗时/状态` 落 `learning_agent_step` |

### 9.5 暂不支持

- **SSE 推送**：当前只做轮询（建议 5–10s 一次）。步骤是逐条落库的，轮询能看到增量，但没有推送通道。
- 任务取消：不支持，提交后只能等结束或超时。
- 跨任务复用中间结果：每个 act 独立，视频总结的缓存靠 `summarize_video` 自身命中，不做任务间缓存。
